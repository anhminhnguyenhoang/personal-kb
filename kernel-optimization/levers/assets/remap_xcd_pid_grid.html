1 · Why we remap PIDs at all

MI355X = 8 XCDs × 32 CUs, each XCD owns a private 4 MB L2. Default HW scheduling fights you.

On MI300/MI355, the GPU is built from 8 XCDs (Accelerator Complex Dies). Each XCD has its own 4 MB L2 cache; they all share an LLC that sits between the L2s and HBM.

  • L2 wants blocks on the same XCD to read overlapping data.
  • LLC wants blocks on different XCDs to read overlapping data.

The hardware dispatches launch-order block IDs round-robin across XCDs (block k → XCD k % 8). Combined with a row-major output-tile walk, this scatters each XCD's work across the whole output → measured 55 % L2 hit rate on a 9216³ BF16 GEMM (HK paper, Table 4).

remap_xcd_chunked and pid_grid re-permute the launch-order block IDs at the top of the kernel to recover spatial locality — no kernel-body changes, ~20 lines of integer math, up to +19 % bandwidth.

The grid is the 2-D output-tile space: row = pid_m, col = pid_n, and the cell number is the linear PID m·N + n. Cell colour = the XCD that PID gets dispatched to under the default round-robin.

Pick any XCD colour and trace it: cells of the same colour land on a diagonal stripe across the grid. Neither rows of A (a single pid_m row) nor columns of B (a single pid_n column) end up on a single XCD — that's the L2-locality problem the two helpers fix.

@triton.jit
def remap_xcd_chunked(pid, GRID_MN,
                     NUM_XCDS: tl.constexpr = 8,
                     CHUNK_SIZE: tl.constexpr = 2):
    xcd = pid % NUM_XCDS
    if pid > (GRID_MN // (NUM_XCDS * CHUNK_SIZE)) * (NUM_XCDS * CHUNK_SIZE):
        return pid                              # tail-guard
    local_pid    = pid // NUM_XCDS
    chunk_idx    = local_pid // CHUNK_SIZE
    pos_in_chunk = local_pid %  CHUNK_SIZE
    return chunk_idx * NUM_XCDS * CHUNK_SIZE
         + xcd * CHUNK_SIZE
         + pos_in_chunk

          trap Maximising L2 hit rate alone usually

          The grid is the output-tile space of a GEMM (rows = M tiles, cols = N tiles).
          Each cell shows the visit order, coloured by which window it belongs to.
          Move the Step PID slider to watch the traversal trace itself.
        

        
    
          
  • GROUP_SIZE_M = 1 → degenerates to row-major.
            Consecutive PIDs share a row of A but burn through all columns of B.
    • 
          
  • GROUP_SIZE_M = W → each window of W PIDs reuses one row of A
            and one column of B (2-D locality). What L2 wants.
    • 
          
  • HK paper sweet spot on 9216³: W = 5.
    • 
        

      

      

        Show the kernel code

@triton.jit
def pid_grid(pid, num_pid_m, num_pid_n,
             GROUP_SIZE_M: tl.constexpr = 1):
    if GROUP_SIZE_M == 1:
        pid_m = pid // num_pid_n
        pid_n = pid %  num_pid_n
    else:
        num_pid_in_group = GROUP_SIZE_M * num_pid_n
        group_id         = pid // num_pid_in_group
        first_pid_m      = group_id * GROUP_SIZE_M
        group_size_m     = min(num_pid_m - first_pid_m, GROUP_SIZE_M)
        pid_m = first_pid_m + (pid %  group_size_m)
        pid_n = (pid % num_pid_in_group) // group_size_m
    return pid_m, pid_n

    •

    • 
          
  • remap_xcd: one giant contiguous block per lane (L2-greedy extreme).
    •

    • 
          
  • pid_grid_3d: cells coloured by k-slab — lanes interleave K, no chiplet awareness.

9 · Takeaways

  

    
    
      
  • Both helpers are HipKittens Algorithm 1.
          remap_xcd_chunked = Phase 1 (XCD grouping, knob C),
          pid_grid = Phase 2 (windowed traversal, knob W=GROUP_SIZE_M).
          Factored as two composable helpers rather than one fused remap — strictly more flexible,
          but the caller has to remember to apply both.
    • 
      
  • remap_xcd = the L2-greedy trap. HK paper explicitly warns
          this configuration costs bandwidth vs the naive baseline. Use the chunked variant and tune C.
    • 
      
  • The defaults in this file are conservative (C=2, W=1 = essentially row-major).
          Meant to be overridden per-kernel/per-shape — wrong defaults silently regress.
    • 
      
  • The 3-D split-K path skips chiplet awareness entirely. Likely a missed lever
          for low-batch sparse-MLA decode where MN scatters across XCDs by default.
    • 
      
  • Pick (W, C) per shape, not globally. Paper's sweet spots differ across problem
          sizes (9216³ wants C=25, 14592³ wants C=64). Always target the bandwidth column, not
          the L2-hit-rate column.
    •
