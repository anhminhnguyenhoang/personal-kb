# aiter architecture: a dispatcher, not a kernel language

aiter ("AI Tensor Engine for ROCm") is AMD's operator library for LLM inference.
It has no kernel language of its own. Each op is a thin Python front end that picks
one kernel from many backends, per shape.

```
 framework call (SGLang / vLLM LinearMethod, attention backend, MoE layer)
        │   gate: SGLANG_USE_AITER=1  /  VLLM_ROCM_USE_AITER=1 (+ sub-flags)
        ▼
 aiter.ops.<family>  /  aiter.tuned_gemm.gemm_a16w16  /  aiter.fused_moe  /  aiter.mla
        │   build key from the live call → look up tuned CSV (aiter/configs/*.csv)
        ▼
 libtype router ── hipblaslt │ asm (.co) │ skinny (HIP) │ triton │ flydsl │ opus │ ck │ torch
        │   first use: @compile_ops JIT-builds the module, caches the .so
        ▼
 kernel launch
```

## Repo layout (what lives where)

| Path | Role |
|---|---|
| `aiter/ops/` | Python op wrappers: the import surface (`gemm_op_*`, `mha`, `attention`, `moe_op`, `moe_sorting`, `topk`, `norm`, `rmsnorm`, `rope`, `quant`, `cache`, `sample`, `shuffle`, collectives) |
| `aiter/ops/triton/`, `aiter/ops/flydsl/`, `aiter/ops/opus/` | Kernels written in Triton, FlyDSL, and the in-tree opus HIP family |
| `aiter/tuned_gemm.py`, `aiter/fused_moe.py`, `aiter/mla.py` | The high-level dispatchers for dense GEMM, fused MoE, and MLA |
| `aiter/configs/` (+ `model_configs/`) | Tuned and untuned per-shape CSVs, one pair per op family; per-model overlays |
| `aiter/jit/` | JIT engine (`core.py`: `@compile_ops`, config resolution), `optCompilerConfig.json` build recipes |
| `csrc/` | C++/HIP/CK sources and the per-family tuners (`gemm_a16w16/`, `ck_gemm_*`, `ck_gemm_moe_2stages_codegen/`, `opus_gemm/`) |
| `hsa/<gfx>/` | Precompiled assembly code objects (`.co`) plus CSV metadata; no `.s` source is shipped |
| `gradlib/` | Older hipBLASLt-only GEMM tuner |
| `op_tests/` | Per-op correctness and perf tests |

## Backends (libtypes)

| libtype | What it is | Typical use |
|---|---|---|
| `hipblaslt` | Vendor GEMM library, called directly (`hipb_mm`) | Most large-M dense GEMM |
| `asm` | Hand-written ISA, shipped as `.co` | Attention decode, MLA, fused-MoE stage 1, some GEMMs |
| `skinny` | HIP split-K GEMV (`wvSpltK`) | Decode GEMM, M = 1..8 |
| `ck` | Composable Kernel template instances | GEMM variants, MoE stage 2, FMHA, norms |
| `triton` | Triton kernels | Fallback and fused or odd shapes |
| `flydsl` | FlyDSL kernels (separate optional package) | Split-K HGEMM, A4W4 MoE |
| `opus` | In-tree split-K HIP GEMM with a reduce kernel | bf16 GEMM, some MoE stage 2 |
| `torch` | PyTorch fallback | Shapes with no tuned row |

The routing details and the tuned-CSV key are in [tuned-config-dispatch](tuned-config-dispatch.md).

## Build and JIT

- Most native modules build on **first call**. The `@compile_ops` decorator reads the
  module recipe from `optCompilerConfig.json`, runs any code generator, compiles with
  `hipcc`, and caches the `.so` (default `~/.aiter/jit/`, override `AITER_JIT_DIR`).
- Asm kernels are not compiled. A generator turns the per-arch CSV metadata into a C++
  table that maps parameters to a `.co` file and symbol.
- CK kernels come from `gen_instances.py` scripts that emit one template
  specialization per tile config.

| Env var | Effect |
|---|---|
| `GPU_ARCHS` | Target archs (`native` or a `;` list such as `gfx942;gfx950`) |
| `ENABLE_CK` | `0` removes every CK-backed op (they fail at call time, not import) |
| `PREBUILD_KERNELS` | Build at install time instead of first call |
| `AITER_REBUILD` | `1` rebuild, `2` rebuild and delete old `.so`: needed after a source or baked-CSV edit |
| `AITER_LOG_LEVEL`, `AITER_LOG_MORE` | Verbose build and dispatch logs |
| `AITER_LOG_TUNED_CONFIG` | Log every tuned-CSV hit or miss (the engagement proof) |

## torch.compile opacity

Dispatchers register as `torch.library` custom ops with a fake (meta) impl. Inductor
then traces *around* them instead of decomposing them into generated Triton. vLLM does
the same thing on its side through `direct_register_custom_op`. A kernel that is not
registered this way gets regenerated by Inductor, and the hand-tuned kernel is lost.

## Framework gates

- **SGLang:** `SGLANG_USE_AITER=1` is the master gate. Without it, dense linear runs
  `F.linear`, and the aiter DB is never consulted.
- **vLLM:** `VLLM_ROCM_USE_AITER=1` is the master gate (default off). Per-family
  sub-flags (`_LINEAR`, `_MOE`, `_RMSNORM`, `_MLA`, `_MHA`, ...) default on once the
  master is on. Selecting an attention backend by name does nothing if the master is off.
- The env surface changes between releases. Check the current `vllm/envs.py` and
  SGLang server args before you rely on a flag name.
